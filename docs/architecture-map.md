# خريطة الاعتماد المعمارية — الوضع الفعلي

هذه الخريطة تسجل البناء الحقيقي منذ جولة الهوية، وليس فهرس «رست 8» أو مزايا مخططًا لها. SQLite محلية؛ PostgreSQL والمزامنة وعزل الشركات غير منفذة.

**استثناء معاينة المالك:** بطلبه أُوقف الدخول مؤقتًا عبر `SMART_PREVIEW_NO_LOGIN=1`. يتخطى الحارس المصادقة والصلاحيات في هذا الوضع فقط، ويستخدم الخادم قاعدة مؤقتة جديدة ولا يسمح باختيار `SMART_DB` أو تفعيل الترحيل. هذا وضع مفتوح بلا حماية وغير صالح لبيانات حقيقية. الخريطة التالية تصف وضع الهوية العادي عندما لا يكون الاستثناء مفعّلًا.

```text
تهيئة محلية تفاعلية --init-admin → identity_users (مرة واحدة فقط)
واجهة Askama + assets/auth.js
  ├─ /api/auth/login → identity.rs → Argon2id + identity_attempts + identity_sessions
  ├─ /api/auth/me, /logout → حارس الجلسة + CSRF عند الخروج
  └─ assets/scripts/*.js → مسارات /api المالية → حارس الجلسة والصلاحيات على الخادم
      ├─ الحسابات → accounts.rs → إعادة فحص المدير داخل معاملة الإنشاء أو تغيير الاسم → accounts
      ├─ المسودات → drafts.rs + domain.rs → إعادة فحص المدير داخل المعاملة → drafts + draft_lines → accounts
      ├─ السندات → vouchers.rs → معاملة IMMEDIATE تعيد فحص المدير في الوضع العادي
      │    → save_draft_in_tx + domain.rs → financial_vouchers مرتبطة بمسودة واحدة
      ├─ الترحيل → ledger.rs + domain.rs + periods.rs + identity.rs
      │    → إعادة فحص جلسة المدير داخل معاملة SQLite IMMEDIATE
      │    → فترة مفتوحة + حسابات + مسودة → journal_entries/posting actor + journal_lines
      ├─ إدارة الفترة → periods.rs + identity.rs → إعادة فحص المدير داخل المعاملة
      │    → financial_periods + period_events/actor
      └─ الأستاذ والميزان وكشف الحساب → ledger.rs → تحقق القيود الكاملة → تقارير (كشف الحساب يستخدم لقطة واحدة للاسم والحركات)
```

- الهوية محلية تجريبية: مدير يملك الكتابة وقارئ للقراءة؛ إنشاء المدير الأول محليًا من طرفية، ولا توجد واجهة إدارة مستخدمين أو تغيير أدوار أو استعادة أو عزل شركات. كلمة السر غير الفارغة تُجزأ Argon2id بملح، والجلسة عشوائية وتحفظ تجزئة رمزها. لا حد أدنى للطول كما طلب المالك، وهذا يترك كلمات المرور القصيرة ضعيفة.
- `identity_users` و`identity_sessions` و`identity_attempts` جداول إضافية. الحارس يطبّق المصادقة على المسارات المالية، وCSRF واشتراط المدير عند الكتابة. الترحيل وإنشاء الفترة أو تغييرها يعيدان فحص الجلسة والدور داخل معاملة الكتابة ويسجلان منفذ العملية الجديدة. السندات تعيد فحص الجلسة والدور داخل المعاملة لكنها لا تسجل المنفذ بعد. مسودات اليومية وإنشاء الحساب وتعديل اسمه تعيد فحص الجلسة داخل معاملتها في الوضع العادي، لكنها لا تسجل المنفذ؛ والمعاينة المفتوحة مستثناة صراحة.
- `journal_entries.posted_by` و`period_events.actor_id` إضافتان مرجعيتان قابلتان للفراغ لحفظ تاريخ القواعد القديمة دون اختلاق هوية. لا يُنسب القديم تلقائيًا لمستخدم أو فترة. الأستاذ يعرض المرحّل المعروف أو «غير معروف»، وسجل الفترات يعرض المنفذ أو «غير معروف». ليس هذا سجل تدقيق متكاملًا لكل العمليات.
- `src/domain.rs` مرجع تحقق القيود والمبالغ العشرية؛ المسودات الجديدة ترتبط بحسابات ولقطات تاريخية؛ المحرك المعاد استخدامه واحد. القيود المرحّلة لا تتغير، ويمنع الترحيل في فترة مغلقة، ولا تنعكس المسودة في الميزان.
- `templates/index.html` و`assets/auth.js`, `assets/scripts/*.js`, `assets/resize.js` للواجهة؛ صحة العمليات والصلاحيات لا تعتمد على JavaScript. `SMART_EXPERIMENTAL_POSTING` مغلق افتراضيًا. لا مصادقة هجين/مركزية، ولا إقفال نتائج أو أرصدة افتتاحية مستقلة أو عكس أو تكامل فواتير ومخزون؛ السندات مرتبطة بمسودات فقط.
- لا تدقيق كامل للهوية وربط المستخدم بكل الأحداث، ولا عزل شامل للسجلات أو سياسات أدوار تفصيلية للشركات والفروع، ولا إدارة مستخدمين أو استعادة آمنة أو مصادقة مهندس أو مفاتيح ترخيص. لا استقرار أمني أو اختبار تحميل أو نشر TLS إنتاجي معتمد. إعداد `SMART_SECURE_COOKIE` لا يوفر TLS بذاته.
- التقارير تتحقق من القيود قبل عرض الحسابات، ولا تُنشئ رصيدًا موازياً؛ عرض الفترة يعتمد فقط على القيود المرحّلة، دون رصيد افتتاحي مستقل أو تحويل عملة. قد يصبح تحقق كل قيود العملة بطيئًا مع كبر البيانات؛ لم يُقَس التحميل.
- `assets/rest8-catalog.json` فهرس يصف 182 شاشة و40 مجموعة وليس دليلاً على بنائها. النظام المرجعي مصدر للاستلهام لا لنسخ العيوب. PostgreSQL المركزي وOutbox والفروع والمزامنة والذكاء والمبيعات والمشتريات والمخزون وتكامل القيد الثلاثي لا تزال خارج التنفيذ الفعلي.

## قرارات وتأثيرات
- `docs/adr/0001-local-identity.md`: قرار ومبررات الهوية المحلية وحدودها وتبعياتها، والهجرة غير المدمرة والاختبارات.
- كل تغيير لاحق يحدّث الخريطة ويحدد الاتصال الحقيقي وفجواته ويختبر السلسلة ولا يفترض وجود وحدة مستقبلية.


## مساحة المالية البصرية المعاد بناؤها (2026-10-30)
`assets/scripts/01-shell-and-catalog.js` يبني شريط أقسام المالية ومساحة العنوان والحالة والتنقل من مكونات التطبيق نفسه، و`assets/style.css` ينفذ الألوان والتدرجات والظلال والاستجابة. ترتيب الأقسام مستلهم من المقارنة البصرية مع المرجع؛ لم تُنقل ملفات شيفرة أو صور منه. المؤشرات غير محسوبة وتعرض شرطة مع توضيح، لا بيانات مختلقة. الأزرار المبنية توجه إلى الشاشات الجزئية القائمة، وغير المبنية إلى تفاصيل عدم التنفيذ؛ لا تضيف هذه الواجهة محركًا أو سجلات مالية أو صلاحيات. لم تتغير بنية القاعدة أو مسارات المحرك. لا تزال شاشات بقية الإدارات وأشكال نوافذها وفروع المالية الكثيرة تحتاج جردًا وإعادة بناء وفحصًا، ولا يعني نجاح تنقل الفهرس تنفيذها.

## تنظيم المصدر في الجولة الحالية

قالب Askama الرئيسي يجمع مكونات متخصصة في `templates/components/`؛ سكربتات الواجهة في `assets/scripts/` تُحمّل بترتيب محدد باستخدام `defer` وتتشارك النطاق العام، وليست وحدات ES مستقلة. ملفات `assets/styles/` تستورد بالترتيب من `assets/style.css`. `tests/source_structure.py` يتحقق من الحد الأقصى البالغ 400 سطر ويحذر من الأسطر الطويلة المتبقية؛ لا يعني النجاح في العدد اكتمال التنظيم أو الوظائف.

## سجل السندات والصفحات

`src/vouchers/list.rs` يقرأ صفحات بمؤشر معرّف وسقف للطلبات المتتالية، ويطبق مرشحات النص والنوع والعملة والتواريخ في الخادم، مع فحص القيد المرتبط لكل نتيجة معروضة في لقطة SQLite لكل طلب. لا تُفحص السجلات خارج الصفحة لأغراض تدقيق شامل، والسقف لا يمثل لقطة ثابتة عبر طلبات HTTP. البحث النصي العام يعتمد `instr(lower(...))` ويطابق العربية كما خُزنت وحالة الأحرف الإنجليزية ASCII، وليس تطبيع Unicode شاملًا أو بحثًا مفهرسًا نصيًا. لم تُقَس كلفته على بيانات كبيرة.


## أساس السجل المالي التجريبي بعد رد المنسقين الأخير

`src/finance_registry/` يعرّف شركات وفروعًا وربط حساب تفصيلي بشركة وأطرافًا وصناديق/بنوك في فرع، دون نسبة البيانات التاريخية تلقائيًا. يرفض ربط حساب له سطور مسودة أو دفتر، ويحدد حسابًا واحدًا لكل طرف أو صندوق تجريبيًا، ويشترط حساب أصول للصندوق؛ هذه قيود تنفيذية أولية لا تمثل سياسة مالية معتمدة شاملة. `src/vouchers/linked.rs` يحفظ سندًا ومسودة متوازنة وسياقها بمعاملة SQLite واحدة ويعيد المحاولة بالمفتاح والحمولة نفسهما، مع التحقق من تطابق الشركة والفرع والعملات. `src/ledger.rs` يمنع ترحيل هذه السندات حتى في الوضع التجريبي. لوحة `templates/components/finance-registry.html` و`assets/scripts/06-finance-registry.js` متاحة من صفحة السندات.

ليس هذا عزلًا شاملًا أو نظام صلاحيات: الفترات والدفتر والتقارير والسندات العادية القديمة لا تُصفى بالشركة، والسجل نفسه يُعرض لكل قارئ مصرح له في الوضع العادي. لا يوجد تعديل أو أرشفة للسجل ولا اعتماد متعدد الأطراف أو تدقيق شامل أو تسوية أو أسعار صرف أو تنفيذ بنكي. لا توجد سياسة مصادق عليها للترحيل بين الشركات والفروع، ولا تحويل أو أرصدة مصرفية. راجع تقرير الجولة للاختبارات والقيود.


## الخط العربي المحلي

يُحمّل `assets/fonts/NotoSansArabic-Variable.ttf` محليًا من `assets/styles/01-shell-and-layout.css` مع ترخيصه `OFL-NotoSansArabic.txt`؛ لا يحتاج إلى CDN. تضبط ملفات الأنماط النصوص الثانوية و`12-readable-typography.css` التباين وحجم بعض حقول الهاتف، ويختبر `tests/ui_typography.cjs` تحميل الخط والتنقل الأساسي بمقاسين. اختلاف المتصفح والخط البديل قد يؤثر في المظهر؛ لا يمثل الفحص شمول جميع الواجهات.


## تمييز داخلي للطبعتين اليمنيتين

`domain::CURRENCIES` مصدر ثابت مشترك للتحقق ولخيارات Askama في الحساب والمسودة والسند وسجل السندات والأستاذ، ويضم `YER-A` و`YER-S` كرمزين داخليين، لا رمزين ISO، و`YER` غير محدد الطبعة حفاظًا على التاريخ. لا توجد هجرة تعيد إسناد أي بيانات. الترشيح والمطابقة يتطلبان الرمز نفسه، ولا يحولان مبلغًا أو يجمعان طبعتين. اختبار `ledger::tests::yemen` يتحقق من حسابين وسندين وترحيل تجريبي محمي وأستاذ/ميزان وفصل الطبعتين عن القديم، وليس عزل شركات أو اعتمادًا إنتاجيًا. لا يوجد نظام تعريف عملات أو أسعار أو تحويل أو تقريب أو عملة وظيفية للشركة.


## إسنادات تنظيمية أولية — ليست عزلًا شاملًا

أُضيفت `finance_company_admins` و`finance_branch_grants` و`finance_grant_events` مع أدوار الفرع وتدقيق المنح والسبب والفاعل. إنشاء شركة/فرع في وضع الهوية يضيف إسناد المنشئ ذريًا؛ السجلات القديمة لا تستقبل إسنادًا بالتخمين. `finance_registry::read` يرشح سجلاته في الوضع المحمي، و`vouchers::linked` يتحقق من كتابة الفرع داخل المعاملة، و`POST /api/finance/grants` يتطلب إدارة الشركة والفرع. لا يطبق الإسناد حتى الآن على بقية واجهات الحسابات والسندات والفترات والتقارير؛ لا يُعتبر النظام معزولًا أو آمنًا للإنتاج. دور المشغل يتطلب كذلك مدير الجلسة حاليًا. لا توجد واجهة لإدارة الإسنادات أو مسار معتمد لإسناد الشركات القديمة.


## دليل الشركة والفترات — تنفيذ تجريبي

`finance_company_account_codes` يربط رقمًا مهنيًا فريدًا داخل الشركة بـ`finance_account_scopes` والحساب الأصلي. الحسابات الجديدة تخزن مفتاحًا داخليًا عشوائيًا في `accounts.code`، وتحافظ على الكود المهني في جدول الربط؛ تهيئة المخطط تملأ الأرقام للحسابات التي كانت مسندة بالفعل دون تخمين ملكية. `accounts::scoped` ينشئ ويعرض الدليل وفق الإسنادات. `finance_period_context` يربط فترة بالمؤسسة و`finance_period_reasons` تحفظ أسباب الأحداث؛ استُبعدت فترات الشركات من `periods::open_period` للقيود القديمة. `vouchers::scoped_read` يقرأ في لقطة مع صلاحية الفرع.

تُحجب المسارات القديمة غير المعزولة بالكامل في الوضع المحمي عبر `legacy_only_preview` حتى لا تتسرب بياناتها؛ ولذلك لا تعمل أجزاء من واجهة الهوية القديمة، ولا يمكن استعراض التاريخ القديم فيها. المعاينة المفتوحة قاعدة مؤقتة ولا تشغل الترحيل وليست أمنًا. لا يزال مسار إنشاء إلى اعتماد وترحيل وأستاذ وميزان معزول غير منفذ، وأي تكامل يقرأ `accounts.code` مباشرة قد يرى المفتاح الداخلي؛ لا يعلن هذا التصميم جاهزية الإنتاج.
