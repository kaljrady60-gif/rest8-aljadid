# التشغيل داخل GitHub Codespaces

هذا المجلد يجعل المشروع قابلًا للبناء والتشغيل والتحكم الكامل من داخل مساحة
GitHub Codespaces، بدلًا من Cloud Shell.

## الملفات

| الملف | الوظيفة |
|---|---|
| `boot.sh` | تهيئة كاملة بخطوة واحدة: أدوات النظام ← Rust ← cloudflared ← تنزيل الكود ← الجسر ← الأنفاق ← البناء |
| `bridge.py` | جسر تحكم HTTP محمي برمز: تنفيذ أوامر، رفع/تنزيل ملفات، فتح أنفاق، قراءة سجلات |

## كيف يعمل الجسر

- يستمع على `8787` داخل المساحة، ويُكشف للإنترنت عبر نفق Cloudflare مؤقت.
- كل طلب يحتاج ترويسة `X-Token`. بلا رمز ⇒ `401`.
- المسارات:

| المسار | الطريقة | الوظيفة |
|---|---|---|
| `/health` | GET | فحص حياة بلا رمز |
| `/run` | POST | `{"cmd":"…","cwd":"…","timeout":240}` ← `{code,out}`؛ و`"background":true` يعيد `{pid,log}` |
| `/put` | POST | `{"path":"…","text":"…"}` أو `{"b64":"…"}` |
| `/get` | GET | `?path=…` ← محتوى base64 |
| `/log` | GET | `?path=…&n=200` ← آخر الأسطر |
| `/tunnel` | POST | `{"port":3300}` ← `{url}` نفق جديد |
| `/ports` | GET | المنافذ المستمعة |

## الضوابط الأمنية

1. الرمز يُولَّد عشوائيًا في كل تشغيل، ولا يُخزَّن في المستودع.
2. النفق مؤقت ويُغلق مع العملية.
3. عند الانتهاء: `pkill -f bridge.py` ثم حذف الأسطر السرية من المحادثة.

## ما لا يفعله

- لا يفتح أي وصول لكتابة خارج `$HOME` بدون صلاحية المستخدم نفسها.
- لا يحتفظ بأي بيانات بين التشغيلات.
